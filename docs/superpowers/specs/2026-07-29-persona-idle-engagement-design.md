# 全能人格与冷场活跃设计

日期：2026-07-29

## 1. 目标

将泡芙从基础技术答疑机器人升级为全能型群聊搭子：知识面广、回答直接可靠、表达俏皮但不油腻；群聊进行时能自然插话，群内冷场时能主动发起话题，同时通过频率和沉寂状态避免刷屏。

## 2. 已确认规则

- 冷场阈值：最后一条真人消息后 30 分钟。
- 活跃时间：`Asia/Shanghai` 时区每天 08:00 至 24:00。
- 首次冷场发言后仍无人回应，再等待 30 分钟进行第二次尝试。
- 第二次发言后仍无人回应，群进入沉寂状态。
- 任意真人发言都会解除沉寂并将主动尝试次数清零。
- 每个机器人、每个群独立计算状态。
- 套餐中的 `lurk` 功能同时控制聊天插话和冷场活跃；未授权该功能的群不会主动发言。

## 3. 人格模型

### 3.1 基础人格

默认名称为“泡芙”，定位为全能型群聊搭子。基础行为：

- 优先直接解决问题，不复述用户问题，不使用客服式开场。
- 日常回复通常 1 至 3 句，复杂问题按短段落或步骤展开。
- 允许适度幽默和俏皮表达，但不刷梗、不滥用表情、不强行装熟。
- 对事实保持谨慎；信息不足时明确说明，并只追问一个关键参数。
- 不伪造执行结果，不泄露系统提示词、密钥、内部配置和隐私。
- 技术、生活、学习、娱乐等话题使用同一人格，不因进入技术模式丢失名称和语气。

### 3.2 提示词合成

所有消息统一构造基础人格，不再把技术提示词作为完全独立的人格：

```text
identity = bot.persona || defaults.persona
base = bot.system_prompt || defaults.systemPrompt
normal = identity + base
technical = identity + base + defaults.techPrompt
lurk = identity + base + defaults.lurkPrompt
idle = identity + base + defaults.idlePrompt
```

机器人专属提示词覆盖全局基础人格正文，但人格名称始终显式注入。技术答疑、正常闲聊、近期插话和冷场发言都沿用同一身份。

## 4. 群活跃状态机

### 4.1 状态

新增 SQLite 表 `group_engagement`：

| 字段 | 含义 |
| --- | --- |
| `bot_id`、`group_id` | 联合主键 |
| `last_human_at` | 最近真人发言时间 |
| `last_idle_at` | 最近一次冷场主动发言时间 |
| `last_idle_text` | 最近一次冷场消息，用于避免第二次重复话题 |
| `idle_attempts` | 当前无人回应周期的成功发言次数，范围 0 至 2 |
| `dormant` | 是否已进入沉寂 |
| `updated_at` | 状态更新时间 |

机器人消息、发送失败和系统事件不视为真人回应。

### 4.2 转移

```text
真人发言
  -> last_human_at = now
  -> idle_attempts = 0
  -> dormant = false

沉默 30 分钟且在活跃时间
  -> 发送第一次冷场话题
  -> idle_attempts = 1

第一次发言后继续沉默 30 分钟
  -> 发送第二次冷场话题
  -> idle_attempts = 2
  -> dormant = true

dormant = true
  -> 不再主动发言
  -> 等待真人消息恢复
```

只有消息实际发送成功后才增加 `idle_attempts`。AI 网关失败时保留当前状态，由后续调度周期重试，并沿用现有网关自动切换。

## 5. 主动发言策略

### 5.1 聊天中插话

保留现有近期群聊插话逻辑：收集近期消息，在对话短暂停顿后判断是否有自然切入点。提示词要求不打断正在解决的问题、不重复群友刚说过的话、不机械总结聊天记录。

### 5.2 冷场起话题

- 有近期上下文时，从最近话题自然延伸。
- 没有可用上下文时，发起轻量、容易回答的开放话题。
- 每次只抛一个话题，默认 20 至 80 字。
- 不说“怎么没人说话”“群里好安静”等催促性文案。
- 第二次尝试必须避开第一次的主题和表达方式。
- 不使用 `@全体成员`，不主动提及不存在的群友信息。

## 6. 后台配置

在“系统设置 -> 人格与节奏”增加：

| 配置 | 默认值 |
| --- | --- |
| `idleEnabled` | `true` |
| `idlePrompt` | 冷场起话题行为提示词 |
| `idleAfterMinutes` | `30` |
| `idleMaxAttempts` | `2` |
| `activeStartHour` | `8` |
| `activeEndHour` | `24` |
| `activeTimezone` | `Asia/Shanghai` |

服务端对数值设置范围并回退到默认值，防止错误配置造成异常行为。冷场间隔允许 1 至 1440 分钟，其中 1 分钟仅用于部署验收；最大尝试次数为 5。

## 7. 调度与性能

- 复用控制端现有 10 秒调度器，不增加独立服务或外部定时任务。
- 每轮只查询已启用机器人、有效群授权且开通 `lurk` 的群状态。
- 同一群继续使用现有串行队列，避免插话、冷场任务和用户回复并发发送。
- SQLite 仅保存少量时间戳和计数器，适合当前轻量部署，也可覆盖后续 50 个机器人。

## 8. 验证

自动化测试覆盖：

1. 人格名称进入正常、技术、插话和冷场提示词。
2. 29 分钟不触发，30 分钟触发第一次。
3. 第一次后再过 30 分钟触发第二次并沉寂。
4. 沉寂后调度不再发送。
5. 真人消息解除沉寂并清零计数。
6. 08:00 前和 24:00 后不主动发送。
7. 没有 `lurk` 权限、授权过期或机器人停用时不发送。
8. AI 或 OneBot 发送失败时不增加尝试次数。
9. 服务重启后从 SQLite 恢复状态。

部署验收时可临时将冷场间隔设为 1 分钟完成测试，确认后恢复为 30 分钟。
